## Session Overview

User provided critical clarifications that significantly simplified the Save Analysis feature scope:

### Key Decisions
1. **No local storage** - Data will be saved by backend API to PostgreSQL
2. **No local management features** - No view/delete/search in the extension itself
3. **Separate viewing application** - A different application (like Anki) will be used to view saved contents

### Updated Scope
The extension now only needs to:
1. Allow users to select words/grammar points from the sidepanel
2. Send save requests to the backend API for selected items
3. Provide basic visual feedback (saved success/fail)

## API Contract Summary

### Endpoint
```
POST /api/v1/save-items
Base URL: http://localhost:8787
```

### Request Body Structure
```json
{
  "items": [
    {
      "type": "word",
      "surface": "漢字",
      "reading": "かんじ",
      "meaning": "Chinese characters...",
      "jlptLevel": "N4",
      "contextSentence": "...",
      "sourceText": "...",
      "sourceUrl": "..."
    }
  ],
  "timestamp": "2025-12-25T20:00:00Z"
}
```

### Response Structure
```json
{
  "success": true,
  "saved": {
    "words": 5,
    "grammar": 2
  },
  "message": "Successfully saved 7 items"
}
```

## Key Technical Challenges

### 1. Markdown Parsing
- **Challenge:** API returns markdown, not structured data
- **Solution:** Parse markdown to extract words/grammar items using regex
- **Risk:** Brittle parsing may fail on edge cases
- **Mitigation:** Comprehensive testing; fallback to save entire markdown

### 2. Backend API Availability
- **Challenge:** Backend API may not be ready
- **Solution:** Mock API for development; keep endpoint configurable
- **Risk:** API contract may change
- **Mitigation:** Clear API contract defined in documentation

### 3. Save Button Integration
- **Challenge:** Save buttons must integrate with existing ruby tag rendering
- **Solution:** Careful CSS and DOM manipulation
- **Risk:** Buttons may interfere with layout
- **Mitigation:** Thorough UI testing
